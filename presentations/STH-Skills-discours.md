# STH — Discours slide par slide

## 1. STH : le skill, du partage à l’usage

Transition : Buddy ouvre le rideau.

Tout commence avec un skill : une façon de faire que quelqu’un a formalisée pour la réutiliser avec son outil IA. Cette personne a trouvé quelque chose d’utile. Maintenant, comment en faire profiter les autres ? C’est le point de départ de Skills Transfer Hub.

## 2. Problème 1 : le skill se disperse

Transition : Buddy pousse.

Aujourd’hui, quelqu’un crée un skill et le partage dans Slack, Google Chat ou Teams. Au mieux, il le met dans GitHub. Le lien circule, chacun récupère sa copie… puis il faut retrouver le bon message, le bon dépôt, le bon fichier. Le partage dépend de celui qui sait où chercher.

## 3. Réponse 1 : retrouver les skills dans STH

Transition : Buddy tire.

Avec STH, on donne aux skills un endroit commun où les retrouver. Le message dans le chat peut annoncer une nouveauté ; la référence reste dans STH. Regardez Buddy : il apporte le skill à un endroit que ses collègues peuvent retrouver. On sait enfin où aller.

## 4. Problème 2 : quelle version utilise chacun ?

Transition : Buddy tourne la page.

Mais retrouver un skill ne suffit pas. Son créateur le corrige, l’améliore, publie une nouvelle version. Pendant ce temps, les autres utilisent encore la copie reçue la semaine dernière. Qui a quelle version ? Et qui sait qu’une correction existe ?

## 5. Réponse 2 : suivre les versions des skills

Transition : Buddy balaie.

STH répond à cette question en donnant de la visibilité sur les versions : ce qui est installé, ce qui a changé et ce qu’on peut mettre à jour. Buddy remplace ici l’ancienne version par la nouvelle. L’objectif, c’est une mise à jour comprise et choisie, avec une référence claire.

## 6. Problème 3 : Codex et Claude

Transition : Buddy dissout.

Il reste un autre problème : moi, je travaille avec Codex ; mon collègue utilise Claude. On veut partager le même skill, mais les formats, les emplacements ou les réglages peuvent différer. Pourquoi faudrait-il refaire cette adaptation à la main à chaque partage ?

## 7. Réponse 3 : adapter le skill à l’outil

Transition : Buddy ouvre le zip.

Le principe de STH, c’est de garder un skill de référence et d’adapter son installation à l’outil cible, parmi les outils pris en charge. Buddy traverse STH avec le skill et le remet sous une forme adaptée. On partage le même savoir-faire, même quand on travaille avec des outils différents.

## 8. Problème 4 : opérations et commerce

Transition : Buddy amortit la chute.

Et tout cela concerne aussi les opérations et le commerce. Ces équipes ont leurs méthodes, leurs tâches récurrentes et leurs propres skills utiles. Si l’accès passe obligatoirement par un dépôt GitHub et une configuration technique, on laisse une partie de l’entreprise de côté.

## 9. Réponse 4 : des skills accessibles aux équipes

Transition : Buddy soulève.

L’objectif est que chaque équipe retrouve les skills utiles depuis ses outils compatibles, avec les droits appropriés. Le partage via MCP ouvre ce chemin : rendre les skills accessibles là où les équipes travaillent déjà. Les opérations et le commerce doivent pouvoir en profiter aussi.

## 10. Roadmap : faciliter la distribution des skills

Transition : Buddy déroule.

La suite s’organise autour de trois axes : des plugins pour regrouper les skills par usage ; le partage via MCP pour élargir leur accès ; et une configuration par équipe pour définir les skills et les réglages utiles. On passe d’un skill partagé ponctuellement à une distribution organisée entre les équipes.

## 11. Démo : un skill, de bout en bout

Transition : Buddy agrandit.

Pour la démonstration, on va suivre un seul skill de bout en bout : le retrouver, vérifier sa version et ses changements, puis regarder son adaptation à l’outil cible. C’est ce fil qui compte : un skill créé par quelqu’un doit pouvoir être retrouvé, maintenu et utilisé par les autres.

## 12. Construisons STH ensemble, en alpha

Transition : Buddy dissout.

Aujourd’hui, nous cherchons des CTO, des team leads et des CEO prêts à tester STH avec nous en alpha. Nous voulons partir de vos usages réels : partager vos skills, les faire évoluer et les rendre utiles à vos équipes. Vos retours nous aideront à choisir les priorités et à construire le projet avec vous. Si vous avez envie de participer, venez nous parler à la fin de la présentation : choisissons ensemble un premier cas à tester.
